### 📅 多智能体小说引擎 MVP - 原子级开发任务清单

#### 🗄️ Phase 0: 本地 Git 状态服务器搭建 (预计 1 天)

**目标**：脱离 Dify 的无状态限制，实现外部持久化。

| **任务 ID** | **模块**  | **原子任务描述**            | **具体操作步骤/代码逻辑**                                                                       | **状态** |
| --------- | ------- | --------------------- | ------------------------------------------------------------------------------------- | ------ |
| **0.1**   | 环境准备    | 初始化本地 Python 后端环境     | 1. `python -m venv venv`<br>2. `pip install flask cors`                               | [ ]    |
| **0.2**   | 数据结构    | 定义 Commit 存储格式        | 在项目根目录创建 `database.json`，初始化一个包含 `commit_id`, `parent_id`, `markdown_payload` 的基础字典。  | [ ]    |
| **0.3**   | 接口开发    | 编写 `GET /checkout` 接口 | 接收参数 `?commit_id=xxx`，从 JSON 文件读取并返回对应的完整 Markdown 字符串。如果为空，返回初始默认状态模板。               | [ ]    |
| **0.4**   | 接口开发    | 编写 `POST /commit` 接口  | 接收 Dify 传来的新 Markdown 文本和日志，生成随机哈希作为新 `commit_id`，打上时间戳并写入 JSON 文件。                   | [ ]    |

#### ✍️ Phase 3: 续写核心与滑动窗口 (预计 3 天)

**目标**：在极低 Token 成本下，稳定输出 5 章正文。

| **任务 ID** | **模块** | **原子任务描述**         | **具体操作步骤/代码逻辑**                                                                                            | **状态** |
| --------- | ------ | ------------------ | ---------------------------------------------------------------------------------------------------------- | ------ |
| **3.1**   | 流程控制   | 配置迭代节点 (Iterator)  | 将敲定的 5 章大纲按章节转化为 JSON 数组 `[章1, 章2, 章3, 章4, 章5]`，作为 Dify 迭代节点的输入。                                           | [ ]    |
| **3.2**   | 代码节点   | 初始化滑动窗口变量          | 在迭代外部定义一个空数组 `Recent_Chapters = []`，用于存放每次迭代生成的正文。                                                         | [ ]    |
| **3.3**   | 生成核心   | 编写极端约束 Prompt      | 在迭代内部放置大模型节点（ DeepSeek-V3）。System Prompt 绑定全局 `Story_Context.md`。User Prompt 输入当前章节大纲 + `Recent_Chapters`。 | [ ]    |
| **3.4**   | 代码节点   | 队列平移 (Queue Shift) | 迭代内部最后一步放 Python 节点：将刚生成的正文 `append` 进 `Recent_Chapters`。如果数组长度 > 2，则 `pop(0)` 剔除最老的一章，防止爆显存。              | [ ]    |

### 💡 为什么需要切得这么碎？

因为 Dify 的 Debug 成本很高。如果一次性连线 10 个节点，一旦报错，你根本不知道是变量没传对还是 JSON 爆了。

按照这个清单，**每勾选一个框，就点击一次 Dify 的“运行单节点”测试**。稳扎稳打，步步为营。
