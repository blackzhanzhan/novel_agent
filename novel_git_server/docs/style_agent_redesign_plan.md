# 文风 agent 重构草案

## 目标

把文风 agent 从“抽象总结 style_guide.md”的单次产物，升级为“近段采样 -> 中文叙事结构指纹 -> 偏差审查 -> 只改文风复写”的闭环。

当前 `style_guide.md` 可以继续作为总纲，但不能再作为唯一风格事实源。续写长篇时，文风约束必须优先来自最近章节和同类叙事功能片段，而不是来自固定题材标签。

## 当前问题

1. 旧文风指南采样范围可能停留在早期章节，无法代表后期章节的成熟风格。
2. 续写 agent 能写出剧情和专业流程，但容易变成流程说明或人物解释剧情。
3. AI 草稿常见问题包括对白推进度偏高、段落节拍偏重、环境压迫感堆料、主题直白。
4. 文风 agent 目前缺少续写后的审查和局部复写能力。

## 新链路

```text
原文章节 / 当前草稿
  -> 近段采样
  -> style_fingerprint 中文叙事结构指纹
  -> style_review 作者可读偏差审查
  -> 续写 agent 获取硬约束
  -> 必要时 rewrite_style_section 只改文风
  -> 人类审阅 / 审查 agent
```

## 去题材化原则

文风 agent 不应先判断小说类型，也不应把固定题材词表当作核心能力。越来越多长篇小说会混合竞技、玄幻、都市、悬疑、系统、金融、群像等结构，强行贴题材标签会误导续写。

文风 agent 应该分析更底层的写作结构：

- 这篇小说如何组织读者注意力。
- 它用对白、叙述、动作、环境还是内心推进剧情。
- 它如何释放信息、制造压力、留下悬念。
- 它的句子和段落如何呼吸。
- 它如何让场景承载情绪，而不是只解释主题。

## 中文指标体系

### 语言呼吸

- **句式呼吸**：平均句长与长短句节奏。
- **段落节拍**：平均段落长度与阅读换气点。

### 叙事推进

- **对白推进度**：人物说话承担了多少剧情推进。
- **动作驱动度**：身体动作和场面调度承担了多少推进。
- **设定解释度**：规则、背景、流程、原因解释的密度。

### 人物贴近

- **内心贴近度**：人物判断、迟疑、误判、情绪反应的密度。
- **视角稳定度**：是否稳定贴近当前视角人物。
- **人声辨识度**：不同角色说话方式是否能区分。

### 场景质感

- **环境压迫感**：空间、声音、光线、温度、气味等是否承载情绪。
- **感官浓度**：感官描写是否足以让场景落地。
- **物件锚点密度**：是否用具体物件固定场景，而非空泛概述。

### 长篇控制

- **悬念留白度**：是否留下未解释的信息缺口。
- **信息释放方式**：直给、延迟、误导、碎片拼接等释放习惯。
- **意象回响**：关键意象是否复现并形成风格记忆。
- **主题直白度**：是否过早替读者说出主题。

## Dify 工作流建议

### 1. 输入

- `book_name`：书库名。
- `active_file`：默认 `style_guide.md`，但后续应允许 `chapter_draft.md`、`summary.md`、`status_card.md`。
- `sample_scope`：例如 `latest_8_chapters`、`same_narrative_function`。
- `draft_chapters`：待审草稿章节号，例如 `162,163,164`。

### 2. Agent 节点职责

文风 agent 应使用 agent 节点，不再依赖暗语 JSON。

它需要明确调用工具：

- 读取最近章节或指定章节。
- 读取 `chapter_draft.md` 中待审章节。
- 生成或请求 `style_fingerprint`。
- 生成 `style_review`。
- 只在用户明确要求时写入 `style_guide.md` 或后续 `style_fingerprint.md`。

### 3. 输出文件建议

- `style_guide.md`：长期总纲，低频更新。
- `style_fingerprint.md`：当前近段叙事结构指纹，中频更新。
- `style_review.md`：针对一次续写草稿的作者可读偏差审查，高频生成。
- `style_constraints_for_continuation.md`：给续写 agent 的硬约束，可由前两者组合生成。

## 给续写 agent 的约束格式

文风 agent 不应只输出文学点评，而要输出可执行约束：

```markdown
## 本轮续写文风约束

- 对白推进度优先贴近原文；必要对白要合并为关键句，避免连续问答替代场景推进。
- 专业流程不能只写步骤和结果，必须落到身体动作、空间压力、人物判断和情绪后果。
- 环境压迫感要服务人物，不要把每个段落都写成感官堆料。
- 段落节拍偏重时，增加自然换气点；不要把整章压成少数超长段落。
- 主题句少而准，优先让动作、场景、沉默和误判证明主题。
- 只改文风时不得改剧情事件、胜负结果、人物行为和章节信息。
```

## 只改文风复写工具构想

后续可以新增 `rewrite_style_section`：

- 输入：文件名、章节标题或行号范围、风格审查意见。
- 约束：不得改变剧情事实、胜负结果、人名、章节顺序、关键设定。
- 输出：复写后的同一段落。
- 审计：复写前后进入 diff 审阅，必须由人类确认。

## 最小接入路径

1. 先保留当前 Dify 文风 agent，不直接发布修改。
2. 用 `novel_git_server/tools/style_fingerprint.py` 在本地生成指纹和偏差审查。
3. 将报告中的“本轮续写文风约束”手动喂给续写 agent 做一次章节复写测试。
4. 如果效果明显改善，再把文风 agent 工作流改成原生工具调用链。

## 验收标准

- 能解释 AI 草稿和原文之间的具体叙事结构差异，而不是只说“文风不像”。
- 能给续写 agent 输出稳定、可执行、可复用的文风约束。
- 不依赖固定题材词表，上传不同类型或混合类型小说仍能工作。
- 不污染正文，不自动改 Dify，不绕过人类审阅。
- 后续接入 Dify 时，文风 agent 的产物可以直接进入续写 agent 的上下文。
