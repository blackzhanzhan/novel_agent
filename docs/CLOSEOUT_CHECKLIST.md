# Closeout Checklist

这份清单用于最后演示冲刺。目标不是把所有想法都做完，而是把项目收口到可以录屏、讲解、写 Wiki、放简历的状态。

## 收口原则

- 优先保证一条完整 demo 路径能跑通。
- 优先展示项目独特性：导入初始化、Agent 创作循环、Git-native 剧情分支。
- 不在最后阶段追求大而全。
- 遇到模型质量问题，优先用审核和错误档案展示系统闭环，而不是假装质量已经完美。
- 每个关键演示点都要有可见 UI、可解释文件、可回滚历史或测试证据。

## P0: 必须演示

这些项目决定 demo 是否成立。

### 1. 本地启动

- [ ] `start_all.ps1` 能启动或检查 Dify、Flask、Vite。
- [ ] 前端可打开 `http://127.0.0.1:5173`。
- [ ] 后端健康检查可用。
- [ ] 空 storage 状态下不会让前端陷入不可解释错误。

验收标准：

- 新环境启动后，用户知道下一步是导入书籍，而不是面对坏掉的默认书。

### 2. 番茄导入初始化

- [ ] 前端 `书籍 / 导入` 能打开。
- [ ] 能输入 `bulk_files` 目录并预览。
- [ ] 预览展示章节数量、字符数、质量风险。
- [ ] confirm 后写入 `chapters/*.md`。
- [ ] 导入后自动打开第一章或可进入新书。
- [ ] 导入章节能被冷档案读取接口读取。

验收标准：

- 观众能看到原文从外部 txt 进入本地创作资料库。

### 3. 读书存档与资料底座

- [ ] 读书存档 Agent 能读取导入章节。
- [ ] 能生成或更新 summary。
- [ ] 世界模型 Agent 能基于原文更新 `world_model.md`。
- [ ] 状态卡只记录 summary 和最新章节后的事实状态。
- [ ] 文风 Agent 输出中文指标体系，不回退到抽象 `style_guide.md`。

验收标准：

- 项目能证明“导入后不是结束，而是变成 Agent 可用资料底座”。

### 4. 大纲链路

- [ ] brainstorm 能从当前资料提出多个创作方向。
- [ ] master outline 能承接选定主张。
- [ ] arc outline 能萃取为阶段结构。
- [ ] chapter outline 能落到逐章节计划。
- [ ] 任意一层可以回流修改，不强迫一次性生成到底。

验收标准：

- 能在 UI 里展示多级大纲不是概念，而是具体文件和 Agent 会话。

### 5. 续写与审核循环

- [ ] 续写 Agent 能读取章节大纲、world、summary、status、style、error archive。
- [ ] 能生成三章草稿到 `chapter_draft.md`。
- [ ] 字数检查和局部扩写逻辑能被解释清楚。
- [ ] 审核 Agent 能给出问题。
- [ ] 人类能在审阅工作台看到 diff。
- [ ] 人类能选择归档、亲自修改或打回续写 Agent 重写。

验收标准：

- 至少完整演示一次：生成草稿 -> 审核 -> 打回局部重写或归档。

### 6. 剧情分支实验室

- [ ] 从同一 brainstorm 或 master outline 派生两个互斥剧情主张。
- [ ] 创建或切换两个 Git 分支。
- [ ] 每个分支能独立生成一组草稿或大纲差异。
- [ ] Git/diff 视图能展示两个路线的差异。
- [ ] 能说明保留、合并、废弃的决策方式。

验收标准：

- 观众能记住：这个项目不是普通 Dify 画布，而是能试写不同剧情宇宙的创作系统。

## P1: 强烈建议完成

这些项目会显著提高演示稳定性。

- [ ] 前端空 storage 状态有明确引导。
- [ ] 导入面板错误信息更作者友好。
- [ ] Demo 样本准备一份小型 `bulk_files`，避免现场搜索或下载不稳定。
- [ ] Dify API key、工作流 ID、模型配置统一检查脚本。
- [ ] 世界模型和文风 Agent 各准备一个短链路压测样本。
- [ ] 审核 Agent 提示词加强，避免只给泛泛文学建议。
- [ ] 续写 Agent 的“局部修改范围”在提示词和工具参数里都讲清楚。

## P2: 可以后置

这些是好想法，但不应阻塞第一版 demo。

- [ ] 真正在线搜索番茄书籍。
- [ ] 更完整的书籍管理 UI。
- [ ] 多本书仪表盘。
- [ ] 更复杂的知识库检索。
- [ ] 自动生成 B 站字幕脚本。
- [ ] 云端部署。
- [ ] 多用户权限。
- [ ] 完整企业化监控。

## Demo 前检查清单

录屏前至少确认：

- [ ] storage 是预期状态。
- [ ] Dify 容器和工作流可用。
- [ ] 前端能打开。
- [ ] 后端健康检查通过。
- [ ] 测试样本目录存在。
- [ ] 至少一个 Dify Agent 能正常工具调用。
- [ ] Git 视图能显示当前书仓库状态。
- [ ] 审阅工作台能进入全屏 diff。

## 简历/视频表达建议

推荐表达：

> 我做的是一个面向长篇小说作者的 AI 创作工作台。它不是简单套一层聊天 UI，而是把小说资料、世界观状态、文风指纹、多级大纲、续写审核和 Git 分支试错组织成一个完整生产流。

避免表达：

- “全自动写百万字小说。”
- “完全解决 AI 幻觉。”
- “模型质量已经等同作者。”

更稳的表达是：

- “把 AI 创作中的幻觉、漂移、试错和人工审阅纳入工程流程。”
- “用 Agent 做语义推理，用 Git 做创作路线管理。”
- “让作者可以低成本试写不同剧情分支。”

## 最后一公里判断

如果只剩两天，优先顺序是：

1. 跑通导入初始化。
2. 跑通一条大纲到续写审核链路。
3. 跑通两个剧情分支的对比演示。
4. 录屏前修前端明显阻断。
5. 再考虑美化和增强。
